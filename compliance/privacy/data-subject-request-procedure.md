# Data Subject Request Procedure

**Document Version**: 1.0  
**Effective Date**: 2026-06-15  
**Review Frequency**: Annually  
**Owner**: Privacy Officer

## Purpose

This document establishes the procedure for handling data subject requests (DSRs) in accordance with GDPR Articles 15-21 and other privacy regulations.

## Scope

This procedure applies to all requests from data subjects to:
- Access their personal data
- Rectify inaccurate personal data
- Erase their personal data
- Restrict processing of their personal data
- Obtain a copy of their personal data (portability)
- Object to processing of their personal data

## Request Verification

### Verification Requirements

Before processing a request, verify the identity of the requester:

| Request Type | Verification Required | Method |
|--------------|----------------------|--------|
| Access | Yes | Email verification or government ID |
| Rectification | Yes | Email verification or government ID |
| Erasure | Yes | Email verification or government ID |
| Restriction | Yes | Email verification or government ID |
| Portability | Yes | Email verification or government ID |
| Objection | Yes | Email verification or government ID |

### Verification Process

1. Request government-issued ID or verify email address
2. Compare provided information with account records
3. Document verification method and result
4. Proceed if verified, deny if not verified

## Request Types and Procedures

### 1. Right to Access (Article 15)

**Purpose**: Provide data subject with copy of their personal data

**Procedure**:
1. Verify identity of requester
2. Retrieve all personal data associated with requester
3. Provide data in structured, commonly used format
4. Include: data categories, recipients, retention period, rights
5. Respond within 30 days of request

**Response Template**:
```markdown
## Data Access Response

**Request ID**: DSR-YYYY-NNN  
**Request Date**: [Date]  
**Response Date**: [Date]

### Personal Data Held
[List of data categories and specific data]

### Data Sources
[Where data was collected from]

### Data Recipients
[Who data has been shared with]

### Retention Period
[How long data will be retained]

### Your Rights
[Summary of data subject rights]
```

### 2. Right to Rectification (Article 16)

**Purpose**: Correct inaccurate or incomplete personal data

**Procedure**:
1. Verify identity of requester
2. Review requested corrections
3. Validate corrections are accurate
4. Update records with corrected data
5. Notify third parties if data was shared
6. Respond within 30 days of request

**Response Template**:
```markdown
## Data Rectification Response

**Request ID**: DSR-YYYY-NNN  
**Request Date**: [Date]  
**Response Date**: [Date]

### Corrections Made
[List of data fields corrected]

### Data Before and After
[Previous value → New value]

### Third-Party Notifications
[List of third parties notified]
```

### 3. Right to Erasure (Article 17)

**Purpose**: Delete personal data when no longer needed or requested

**Procedure**:
1. Verify identity of requester
2. Assess if erasure is permitted (legal obligations, legitimate interest)
3. If permitted, delete data from all systems
4. If not permitted, explain reason
5. Notify third parties if data was shared
6. Respond within 30 days of request

**Exceptions to Erasure**:
- Legal obligation to retain data (e.g., HIPAA 7-year retention)
- Exercise of right of freedom of expression and information
- Compliance with legal obligation
- Establishment, exercise, or defense of legal claims
- Public interest in public health
- Archiving purposes in public interest
- Research purposes (with safeguards)
- Exercise or defense of legal rights

**Response Template**:
```markdown
## Data Erasure Response

**Request ID**: DSR-YYYY-NNN  
**Request Date**: [Date]  
**Response Date**: [Date]

### Erasure Status
[Approved/Denied]

### Data Erased
[List of data deleted]

### Reason for Denial (if applicable)
[Explanation]

### Third-Party Notifications
[List of third parties notified]
```

### 4. Right to Restrict Processing (Article 18)

**Purpose**: Limit processing of personal data while accuracy or lawfulness is disputed

**Procedure**:
1. Verify identity of requester
2. Restrict processing to storage only
3. Notify requester when restriction is lifted
4. Respond within 30 days of request

**Response Template**:
```markdown
## Processing Restriction Response

**Request ID**: DSR-YYYY-NNN  
**Request Date**: [Date]  
**Response Date**: [Date]

### Processing Restricted
[List of data with restricted processing]

### Duration of Restriction
[Time period or until condition met]

### Conditions for Lifting Restriction
[What must happen to lift restriction]
```

### 5. Right to Data Portability (Article 20)

**Purpose**: Obtain personal data in structured, machine-readable format

**Procedure**:
1. Verify identity of requester
2. Export data in structured format (JSON, CSV)
3. Provide data directly to requester
4. Facilitate transfer to another controller if requested
5. Respond within 30 days of request

**Response Template**:
```markdown
## Data Portability Response

**Request ID**: DSR-YYYY-NNN  
**Request Date**: [Date]  
**Response Date**: [Date]

### Data Exported
[List of data categories exported]

### Format
[JSON, CSV, etc.]

### Transfer to Another Controller
[Yes/No, and details]
```

### 6. Right to Object (Article 21)

**Purpose**: Object to processing based on legitimate interest

**Procedure**:
1. Verify identity of requester
2. Assess if legitimate interest overrides objection
3. If objection granted, stop processing
4. If objection denied, explain compelling legitimate grounds
5. Respond within 30 days of request

**Response Template**:
```markdown
## Objection to Processing Response

**Request ID**: DSR-YYYY-NNN  
**Request Date**: [Date]  
**Response Date**: [Date]

### Objection Status
[Granted/Denied]

### Processing Stopped
[List of processing stopped]

### Reason for Denial (if applicable)
[Compelling legitimate grounds]
```

## Response Timeframes

| Request Type | Standard Response | Extension Possible |
|--------------|-------------------|-------------------|
| Access | 30 days | Yes, up to 90 days |
| Rectification | 30 days | Yes, up to 90 days |
| Erasure | 30 days | Yes, up to 90 days |
| Restriction | 30 days | Yes, up to 90 days |
| Portability | 30 days | Yes, up to 90 days |
| Objection | 30 days | Yes, up to 90 days |

## Extension Process

If additional time is needed:
1. Notify requester within 30 days
2. Explain reason for extension
3. Provide new response date
4. Document extension in request record

## Record Keeping

Maintain records of all data subject requests including:
- Request ID and date
- Requester identity (verified)
- Request type
- Verification method
- Response provided
- Response date
- Any extensions granted
- Third-party notifications

## Third-Party Notifications

When data is rectified, erased, or restricted:
1. Identify all third parties who received the data
2. Notify third parties of the action taken
3. Request third parties take appropriate action
4. Document notifications sent

## Denial Process

If a request is denied:
1. Provide clear reason for denial
2. Explain requester's right to lodge a complaint
3. Provide contact information for supervisory authority
4. Document denial and reason

## Roles and Responsibilities

| Role | Responsibilities |
|------|------------------|
| Privacy Officer | Receive requests, coordinate response, ensure compliance |
| Data Protection Officer | Review requests, provide guidance |
| System Administrator | Execute data changes (erasure, rectification) |
| Legal Counsel | Review complex requests, provide legal guidance |

## Metrics

Track and report quarterly:
- Number of requests by type
- Average response time
- Number of requests granted/denied
- Number of extensions granted
- Number of third-party notifications
